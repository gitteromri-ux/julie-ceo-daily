Meta tracking audit: Longevity Blueprint & Masterclass funnels

Checked Wed 4 Nov 2026, 18:30–19:30 Israel time. Read-only: nothing on the site, Meta, Cloudflare or Vercel was changed. Every finding is marked VERIFIED (seen directly) or ESTIMATE (reasoned, not proven).

Bottom line

The pixel is not broken. On iPhone, Android and desktop the ad landing page sends PageView, AddToCart and InitiateCheckout to the right pixel (1440305917310328), each with a matching server copy for deduplication. The Purchase code is in place.

VERIFIED The ad sets show "zero pixel events" today for three reasons. (1) The ad landing page never sends ViewContent, in any version deployed since 7 Oct. Every ViewContent the ad sets ever got came from www.longevitylifeacademy.com/julie-masterclass, a different page. (2) From about 3 Nov 21:00 to 4 Nov 16:09 the checkout was blocked by the Cloudflare Access gate, so no InitiateCheckout or Purchase was possible. (3) Traffic is very low (today 1–11 landing page views per ad set), and attributed conversions can show up hours late.

Terms in plain English

PixelMeta code in the browser that reports what a visitor does. Our pixel/dataset id is 1440305917310328.
CAPI (server copy)The same event sent from our server (lla-ac-events.vercel.app), so ad blockers and iOS don't lose it.
event_id / dedupA shared id on the browser and server copies, so Meta counts the pair once.
Landing page viewMeta's own count of ad clicks where the page loaded. It is not a pixel event.
ViewContent / AddToCart / InitiateCheckout / PurchaseFunnel steps: viewed product → started enrolling → submitted details and got an order → paid.
promoted_objectThe pixel and event an ad set optimises for.

5. Why the ad sets show no pixel events

Wrong pixel?VERIFIED No. The page, server and all 4 promoted_objects use 1440305917310328.
Pages not firing?VERIFIED Only ViewContent. The ad landing page has never sent it. So "36 landing page views and 0 ViewContent" is expected. The Lists set's 7 ViewContent and the Masterclass sets' high ViewContent came from visits to /julie-masterclass on .com, for example the paused Ad#21, which linked there.
Checkout blocked?VERIFIED From about 21:00 on 3 Nov to 16:09 on 4 Nov the CRM proxy was gated. InitiateCheckout waits for the CRM order, and Purchase waits for payment, so neither could fire. AddToCart also disappeared in that window ESTIMATE: it most likely depends on the ecommerce layer reaching the proxy.
Attribution delay / low volume?ESTIMATE Today each set had 1–11 landing page views. At the 14-day AddToCart rate of about 5.7% per landing page view, a set expects 0–1 AddToCart a day. Zero is normal noise, and Meta can add attributed events several hours later. Interests: 36 link clicks and 28 landing page views in 14 days, with about 1.6 AddToCart expected, so 0 is about a 1-in-5 chance.

6. Proposed fix (PROPOSAL only, nothing changed)

  1. Add a ViewContent event to the ad landing page (pages.dev/, and its .com mirror if one is used). Fire it once per visit after the page loads, with content_ids [the Blueprint CONTENT_ID], value 79 and currency USD. Use the same eventID pattern as PageView (lla_viewcontent_<session>), and add a server copy through lla-ac-events. That needs 'ViewContent' added to the EVENTS list in api/meta/capi.js, because today the relay would reject it. This makes the top of the funnel readable per ad set.
  2. Stop gating the CRM proxy (eteacher-leads-proxy) with Cloudflare Access. Or add a bypass policy for the public /api/lead/ecomm and /api/checkout/* paths and an uptime alert, so InitiateCheckout and Purchase can't silently stop again.
  3. Add the standard url_tags (the cid / adGroupID / utm_* block) to the 8 active ads that have none, so CRM leads carry their campaign.
  4. Re-check this in 24–48 h. Ad-set AddToCart, InitiateCheckout and Purchase for 4 Nov afternoon onward should appear, delay included.
