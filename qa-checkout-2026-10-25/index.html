Masterclass $49 checkout: QA report

Date: 25 Oct 2026. All times are Israel time (UTC+2 from 25 Oct; UTC+3 before that). Anything not proven is marked ESTIMATE.

1. Summary

Page: longevitylifeacademy.com/julie-masterclass/

On iPhone 14, iOS 16.4, Safari (BrowserStack), the payment form fails with this message: "We could not open the payment form for your package, so nothing was charged. Please try again in a moment or contact advisor@longevitylifeacademy.com. Reference: PAYMENT_FORM_UNAVAILABLE". It happened twice, at about 13:46 and 13:56 on 25 Oct.

On desktop Chrome at 13:49 it works. The Airwallex drop-in loads with Apple Pay, Google Pay, card fields and a "Pay 49.00 USD" button.

Result: the checkout failed on 2 of 2 iPhones that reached the payment step (iPhone 14 iOS 16.4 twice, iPhone 13 iOS 17.5 once). Desktop Chrome passed.

VERIFIED by the iPhone 13 console: the Airwallex payment SDK (window.Airwallex) never loaded on the iPhone.

Not yet tested: iPhone 15, iPhone 15 Pro Max and iPhone 12, because of BrowserStack boot failures and lack of time.

ESTIMATE: the problem is specific to iPhone Safari. We have not yet ruled out BrowserStack connectivity.

3. Retest on 25 Oct

4. Code diagnosis (read-only)

  • The error is thrown by inline script in the julie-masterclass page HTML.
  • Line 3493 waits up to 15 s for window.Airwallex (a Promise.race with JULIE_AWX_WAIT).
  • Line 3495: if !awx||!awx.init, it logs "payment SDK not loaded" and throws PAYMENT_FORM_UNAVAILABLE.
  • Line 3510: it calls awx.createElement('dropIn', JuliePaymentSafety.dropInOptions(d)). If that returns null, it logs "payment form could not be built" and throws.
  • Line 3598: the handler that shows the error message.
  • VERIFIED: backend order or intent failures, and an Airwallex.init rejection, show different references. They are ruled out.
  • The Airwallex bundle elements.bundle.min.js?version=1.160.0 parses on iOS 16. We found no incompatible syntax.
  • The drop-in requests three methods: card, googlepay and applepay. On Safari only, the SDK also loads an Apple Pay script from applepay.cdn-apple.com. That fits the pattern of a Safari-only failure.
  • The Airwallex bundle was last modified 23 Oct at 06:50 Israel time (03:50 UTC). It is cached for only 5 s.
  • The page is served by GitHub Pages. It was last modified 25 Oct at 11:52 Israel time.
  • ESTIMATE, root cause: one of two things. Either the SDK does not load on iOS Safari (or over BrowserStack's network), or the drop-in refuses to build on Safari because of Apple Pay. To confirm, we need the console message from an iPhone.

4b. Common-iPhone run, 25 Oct 14:09 Israel time

  • iPhone 15 (iOS 17) did not boot on BrowserStack within about 65 s, so we skipped it.
